SECTION 2
Data Architecture
Incremental simulation → JSONL partition → Medallion Lakehouse
🔄 Incremental Data Flow — Thiết kế cốt lõi
Thay vì dump CSV một lần, mỗi 15 phút simulator sinh ra một "window" data mới dạng JSONL — giống hệ thống thật đang ghi log liên tục. Airflow DAG detect file mới → ingest vào Bronze Delta → Silver → Gold. Dashboard luôn fresh.
🚗 Simulator — Sinh data có state
Cách hoạt động
Lần đầu: khởi tạo pool 500 drivers + 2000 riders → lưu state.json
Các lần sau: dùng lại pool cũ — rider_id/driver_id overlap realistic
Thêm nhỏ giọt: 0-3 drivers mới, 5-20 riders mới mỗi batch
trip_counter tăng liên tục — trip_id không bao giờ trùng
Demand theo giờ: rush hour 7-9h, 17-19h tự nhiên từ DEMAND_BY_HOUR
Output mỗi 15 phút
Format: JSONL (1 event / dòng — append-friendly)
Path: data/raw/trips/date=2026-03-21/hour=14/batch_1430.jsonl
~40-60 trips / batch (biến động theo giờ)
Riders/drivers mix cũ + mới → realistic churn
Denormalized nhẹ: kèm driver_tier, rider_segment, payment_method
📁 Partition Structure trên MinIO

🏗️  Medallion Architecture — 3 Layers
🥉  BRONZE — Raw Landing
Raw JSONL → Delta Lake, append-only — không transform
Partition: _date / _hour (Hive-style)
Retention: 60 ngày — có thể replay bất cứ lúc nào
Great Expectations: schema + volume + freshness checks
Time travel: query data của 3h trước khi cần debug
🛠️  Stack
Airflow DAG (run_simulator + ingest_to_bronze)
Delta Lake on MinIO (ACID, time travel)
Great Expectations (quality gates)
Postgres table pipeline_runs (monitoring)
🥈  SILVER — Clean & Conform
PySpark: dedup trip_id, cast types, mask PII (phone)
Validate lat/lng bounds (HCMC/HN geography check)
Enrich: join driver_tier, rider_segment từ state
dbt staging: stg_trips, stg_drivers, stg_riders
dbt tests: not_null, unique, accepted_values, relationships
🛠️  Stack
PySpark incremental (chỉ đọc partition mới)
dbt Core — staging + intermediate models
Delta Lake ACID (no dirty reads concurrent writes)
pytest cho PySpark unit tests
🥇  GOLD — Business Ready
fact_trips: 1 row / trip (Kimball star schema)
dim_driver, dim_rider, dim_zone, dim_time
daily_trip_summary, driver_weekly_scorecard
demand_heatmap: zone × hour aggregation
dbt docs: auto-gen catalog + lineage graph
🛠️  Stack
dbt incremental mart models
Delta Lake Z-order optimization
Spark SQL / Trino (Metabase query engine)
dbt source freshness — alert khi data stale
🤖 AI Add-on (Phase 4 — không block pipeline)
AI layer chỉ READ từ Gold — pipeline core chạy hoàn toàn độc lập. Nếu AI có bug, dashboard vẫn hoạt động bình thường.
🔮  Demand Forecasting (Prophet)
Input: demand_heatmap Gold table (7 ngày gần nhất)
Model: Prophet — đơn giản, interpretable, không cần GPU
Output: forecast trips theo zone × hour (next 24h)
Airflow DAG retrain mỗi tuần (Sunday 2:00 AM)
Kết quả push vào Gold demand_forecast table → Metabase
🚨  Anomaly Detection (Z-score)
Monitor: cancellation_rate + driver_utilization theo giờ
Z-score đơn giản — không cần ML phức tạp, explainable
Threshold: |z| > 2.5 → ghi vào Postgres alerts table
Metabase alert → email khi metric bất thường
Root cause: SQL query tự động gắn theo mỗi alert

🎤 Interview Q&A
Câu hỏi
Trả lời — dùng RideFlow
"Walk me through your pipeline"
Mở đầu bằng business problem: 'Ops team cần biết realtime demand để dispatch driver.' Rồi: simulator sinh JSONL mỗi 15 phút (stateful — reuse rider/driver IDs) → Airflow DAG 4 tasks → Bronze Delta partition by date/hour → PySpark Silver (incremental) → dbt Gold → Metabase. Nhấn vào: tại sao JSONL thay CSV, tại sao partition by hour.
"Tại sao JSONL thay vì CSV?"
CSV không append-friendly — phải đọc lại file cũ để thêm. JSONL: mỗi dòng là 1 JSON object độc lập, append bằng cách ghi thêm dòng. Airflow FileSensor detect file mới không cần scan toàn bộ thư mục. Ngoài ra JSONL có schema embedded — dễ validate từng record.
"Incremental pipeline hoạt động thế nào?"
3 tầng: Bronze (append Delta partition mới), Silver (PySpark chỉ đọc partition _date/_hour mới nhất từ Bronze), dbt Gold (incremental model với is_incremental() filter: WHERE request_time > max(request_time) IN target). Mỗi layer chỉ process data mới — không recompute toàn bộ.
"Tại sao Delta Lake thay vì Parquet thuần?"
ACID transactions — tránh dirty reads khi Airflow + Spark write đồng thời. Time travel — query data của 3h trước khi debug anomaly. Schema evolution với mergeSchema=true — thêm column mới không cần rewrite. Câu này bạn đã học kỹ từ day06-delta-lake — trả lời tự tin với ví dụ cụ thể.
"dbt là gì, tại sao không dùng Spark thôi?"
Spark giỏi heavy lifting (dedup, ML features, UDF). dbt giỏi business logic bằng SQL + built-in testing + auto-generated documentation + lineage graph. Dẫn reviewer xem dbt docs site: thấy lineage từ stg_trips → int_trip_enriched → fact_trips ngay lập tức. Đây là thứ Spark không có.
"Project nhỏ so với production thật"
Đồng ý — đây là local dev environment với synthetic data. Nhưng pattern giống production: stateful incremental ingestion, partitioned storage, layered architecture. Scale path rõ ràng: MinIO → S3, local Airflow → MWAA, local Spark → EMR. Interviewer muốn biết bạn hiểu pattern, không phải bạn đang chạy petabyte.
